## 4. How the new pieces fit (implementation today)

```
PortalRunner.run
  -> AgentActions(...).register_all()
  -> try: _run_agent(agent)  finally: actions.finish_job()

check_applied(url)          -> not_applied: finish_job(), then remember url as the listing
mark_applied(url, ...)      -> job_url = remembered listing (or url), apply_url = url if different,
                               submit_seen = any POST captured since the job started,
                               then NetworkRecorder.start_job() (forget this job's POSTs)
mark_attempted(...)         -> record, then start_job()
finish_job()                -> real run: UnmarkedSubmits.record(recent POSTs); always start_job()

NetworkRecorder.attach_if_needed(session)
  -> Network.enable + Page.enable on the page session
  -> handlers (through add_cdp_handler): requestWillBeSent, Page.frameNavigated (FrameUrls),
     Target.attachedToTarget (FrameSessions: enable Network/Page + getFrameTree per iframe)
  -> each capture: url, document_url, page_url, resource_type, body, headers
```

`UnmarkedSubmits` counts a capture only when it has a `page_url`, is not a beacon
(`resource_type` `Ping`), and its request host equals the page host. Analytics on the
page's own host still counts; such hosts belong in `NetworkRecorder.NOISE_FRAGMENTS`.

## 5. What was discovered

1. **browser_use cuts actions silently.** `agent/service.py` keeps
   `parsed.action[: max_actions_per_step]` with no log and no message to the model; its
   memory then says the form is filled. With the default 5, flash-lite filled 4 of 14
   fields and the browser blocked the submit.
2. **browser_use's `input` action can append.** Its `clear` field is described only as
   `'1=clear, 0=append'`. flash-lite sent `clear: False` when it typed into a field
   again, so phone, LinkedIn and website were sent twice in one run.
3. **The agent passes the form URL to `mark_applied`**, not the listing URL it checked.
   `job_url_key` keeps the path, so the next run's `check_applied` on the listing said
   `not_applied` and the same application was sent again (fixed, 3.3).
4. **flash-lite may skip `check_applied` and `mark_applied` entirely** (run D, section 7):
   a form was sent and nothing was recorded.
5. **flash-lite may call `mark_applied` when no POST went out** (run E): the job is
   recorded as applied but was never sent. Now flagged `submit_seen: false`.
6. **A cross-site iframe has its own CDP session.** The recorder saw 0 of 2 POSTs from a
   `localhost` iframe inside a `127.0.0.1` page; with a same-site iframe it saw both.
   Requests an iframe sends before its session is enabled are still missed.
7. **For a form submit, `documentURL` is the POST target**, not the page with the form;
   `Referer` is not in `Network.requestWillBeSent` headers.
8. **browser_use's own loop detector is soft** (nudges from 5 repeats, "carry on if
   making progress"). Context messages added from the step callback are cleared before
   the next LLM call, and `Agent.add_new_task` replaces the task, so `ScrollLoopBrake`
   writes to `agent._message_manager.state.agent_history_items` (private browser_use API).
9. **Both models answered Veteran/Disability "I prefer not to answer"** in 2 of 3 runs
   although the profile has answers. Likely cause, not proven: the profile wording does
   not match the option text, and the profile section header says "skip if optional".
10. **A dry run can cost more than a real run**: run C (dry, flash) used 48 steps,
    US$ 0.569, against 16 steps and US$ 0.172 for the real run A.
11. Test servers for Chrome must be `ThreadingHTTPServer`: a single-threaded
    `HTTPServer` stalled an iframe load by about 40 s (Chrome keeps a preconnect socket open).
12. OpenRouter key `usage` did not change across one run late in the session; it can lag,
    so a cost read right after a run may be wrong.

## 6. What is still open (none fixed in this session)

Each item says when it is done.

1. **`clear: False` sends a value twice.** Fix idea: in `StepCallback.on_step` (runs
   before the actions), set `clear=True` on every `input` action. Done when a test proves
   it and a flash-lite local run shows no doubled field.
2. **`--max-actions 5` cuts form fills short.** Fix idea: raise the default (README
   suggests 8-12) and log a warning when browser_use would drop actions. Done when the
   default flash-lite local run sends both forms, or the default is changed on purpose.
3. **`mark_applied` with no POST is still recorded as applied** (`submit_seen: false`).
   Done when such records are reviewed or handled (for example kept out of
   `check_applied`'s skip), decided with data from real runs.
4. **An agent that never calls `check_applied` can still apply twice**: `UnmarkedSubmits`
   only helps when `check_applied` is called on the next run. Done when a duplicate submit
   is blocked even without `check_applied`, or this is accepted on purpose.
5. **Veteran/Disability answers** (5.9). Done when the user decides on the profile wording
   (`knowledge/` is the user's file: tell the user, do not edit it).
6. **Scroll brake effect** measured in 1 WWR run only. Done after 3 or more flash-lite WWR
   runs compared with the earlier ones.
7. **Not yet seen live**: a real Greenhouse form embedded in a company page (only the
   local cross-site iframe test), and the guard blocking a final submit clicked by the
   agent (the agent never clicks it in a dry run).
8. **Review findings left**: `StepCallback` extracts actions twice; `PortalRunner` is
   built the same way in two places; two request-id sets grow without limit over a run.

## 8. How the local end-to-end test was built (to repeat it)

The scripts lived in the session scratchpad and are **not in the repo**. To rebuild:

1. **Fake portal:** a `ThreadingHTTPServer` on `127.0.0.1:8765` that serves a listing
   (`/`) with two remote Python roles, a job page per role, and an apply form per role
   built from `tests/fixtures/forms.py` (job 1: `GREENHOUSE_FORM + EEO_FORM`, job 2:
   `LEVER_FORM + WORKDAY_COMPENSATION + ASHBY_TECHNICAL`). Each field is a real input
   (`text`, `email`, `tel`, `select`, `radio`, `checkbox`, `textarea`, `file`) named by a
   slug of its label, `required` when the fixture says so. `POST /jobs/<id>/apply` parses
   the multipart body and appends `{job, fields, files: {name: {filename, size, pdf}}}` to a
   JSONL file, then shows a "Thank you" page.
2. **Sandbox:** a directory with symlinks to `fill.py`, `prompts/` and `.env`, and a
   `knowledge/` dir with symlinks to every profile file except `07_agent_notes.md`, which
   is copied (so `save_note` cannot write to the real one). `Paths.ROOT` comes from
   `Path(__file__).parent` without resolving the link, so `applied.jsonl`, logs, profiles
   and screenshots stay in the sandbox. A `systems.yaml` there has one entry pointing at
   `http://127.0.0.1:8765/`.
3. **Run:** `cd <sandbox> && uv run --project <repo> python <sandbox>/fill.py --systems <sandbox>/systems.yaml --system acme_local --headless --max-actions 12 [--model ...] [--dry-run]`.
   In zsh call it through a shell function, not a `$CMD` string (zsh does not split it).
4. **Check:** compare each submitted field with the row of `knowledge/00_form_answers.md`
   for that question (whole-word match, flag a value that contains the expected value
   twice), and compare the uploaded file size with `RESUME_PATH` without printing it.

## 9. What to watch in real runs

| Signal | Where | What it means |
|---|---|---|
| `submit_seen: false` in `applied.jsonl` | records | the agent marked a job applied with no POST captured; check by hand whether it was sent |
| `reason: submitted_not_marked` in `attempted.jsonl` | records | a form POST with no `mark_applied`; the application may have gone out. If the page is analytics on the job site's own host, add the host to `NOISE_FRAGMENTS` |
| `mark_applied with no POST seen` | run log, WARNING | same as `submit_seen: false` |
| `submitted without mark_applied, recording` | run log, WARNING | same as `submitted_not_marked` |
| `scroll brake: N scroll-only steps` | run log, INFO | the brake fired; what the next step does tells whether it works |
| `HTTP 4xx/5xx` + `http_error` event | run log / `events.jsonl` | a server answer that may be a rejected form |
| `step_callback_error` mentioning `_message_manager` | `events.jsonl` | a browser_use upgrade broke `ScrollLoopBrake` (private API) |
| fields doubled or empty | `applications/<portal>/network/*_post.json` bodies | items 6.1 and 6.2 |
| dry-run cost | OpenRouter key `usage` | dry runs can cost several times a real run (5.10) |

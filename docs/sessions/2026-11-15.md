  saw) and `stepNNNN_after.png` (the page after the actions ran), in
  `screenshots/<portal>/<run_id>/`. A portal retried in the same run writes to
  `<run_id>-2`.
- Four open items from [2026-10-30.md](2026-10-30.md) section 6 are closed or narrowed:

## 2. Commits (one change each, each with its test)

1. **`--max-actions` default 12** (`RunOptions.DEFAULT_MAX_ACTIONS`). With 5, flash-lite
   filled 4 of 14 fields on 2026-10-30.
2. **`InputClearer`**: every `input` action gets `clear=True` before browser_use runs it.
   The step callback receives the same action objects browser_use executes
   (`agent/service.py`: `self.state.last_model_output` goes to the callback, then to
   `multi_act`), and the dynamic `ActionModel` is a `RootModel`, so the params live at
   `action.root.input`. The test uses the real `ActionModel` from `Tools().registry`.
3. **Review findings**: action names come from the details (read once);
   `--system` builds its runner through `Orchestrator.make_runner`; `CDPDebugger` forgets a
   request on `Network.loadingFinished` / `loadingFailed`; `NetworkRecorder` keeps only the
   ids of POSTs it records.
4. **Before/after screenshots** (`StepShots`, `ShotPhase`, `StepCallback.on_step_end`,
   passed as `agent.run(on_step_end=...)`). browser_use bumps `n_steps` before
   `on_step_end`, so the step that just ended is `n_steps - 1`. The after shot uses
   `StepShots.capture` (CDP `Page.captureScreenshot` under a 6 s limit), not
   `BrowserSession.take_screenshot`, which has no limit and raises a bare `Exception` on
   an empty reply. A failed capture is logged as `step_callback_error`. The
   `save_screenshot` tool still writes `submit_<time>.png` to `screenshots/<portal>/`.
5. **`AppliedPageStop`** (with `KnownJobs`): each step, before the actions run, the page
   URL is checked against `applied.jsonl` and the attempts the agent recorded. On a match,
   `click`, `input`, `upload_file`, `send_keys`, `select_dropdown` and `evaluate` are
   dropped, a note goes to the agent history, and if nothing is left a `go_back` takes
   their place.
   - The portal start URL never counts: in the real `attempted.jsonl`, 1 of 16 records
     named a start URL (reason `captcha`), counted with `job_url_key` against every
     `systems.yaml` URL.
   - `submitted_not_marked` records are ignored by the stop (they can name a listing).
     `check_applied` still skips them. So an agent that sends a form without marking it
     **and** skips `check_applied` next time can still send it twice: narrower than
     before, not closed.
   - browser_use `_finalize` returns before `n_steps += 1` when `last_result` is empty;
     that is why the empty list is replaced with `go_back`.

## 3. Obscura: what was measured, why it was dropped

All runs through browser_use 0.12.6 over CDP to `obscura serve` 0.2.7 (stealth build),
local machine, probe scripts in the session scratchpad (not in the repo).

| Check | Obscura | Chrome |
|---|---|---|
| `BrowserSession.start()` | 0.29 to 0.38 s | 1.39 to 11.79 s |
| We Work Remotely search page title | `We Work Remotely: Advanced Remote Job Search` | `Just a moment...` |
| DOM text for the LLM, Greenhouse / Ashby / Lever | 7336 / 7058 / 36576 chars | 2456 / 1744 / 2649 chars |
| `tests/test_dry_run_guard_chrome.py` logic | server got `['/api/submit', '/apply']` | blocked |
| `Fetch.requestPaused` | only with `sid=True` (page session) | (guard test passes) |

Form submit with a text field and a file, value set by JS, file set by
`DOM.setFileInputFiles` (probe output, trimmed):

```
obscura  multi click           application/x-www-form-urlenco len=7 b'a=hello'
obscura  multi fetch-formdata  multipart/form-data; boundary= len=137
chrome   multi click           multipart/form-data; boundary= len=291
chrome   multi fetch-formdata  multipart/form-data; boundary= len=291
```

Obscura sends text fields (a replay of the local apply form gave
`application/x-www-form-urlencoded len=143`) but never the file. Other facts found while
wiring it, kept here in case Obscura is tried again:

- `obscura serve --port 0 --ready-file F` writes `{"pid":..,"host":"127.0.0.1","port":..}`
  about 0.4 s after start, so no port race.
- `DOM.setFileInputFiles` needs `--allow-file-access`.
- browser_use with `is_local=False` lets `upload_file` take **any** path
  (`tools/service.py`: "For remote browsers ... we allow absolute remote paths"). A CDP
  browser on this machine must use `BrowserProfile(cdp_url=..., is_local=True)`.
- browser_use already refuses agent navigation to `file://` (`SecurityWatchdog`:
  "Navigation to file:///... blocked by security policy"); page JS on Obscura could not
  read `file://` either (`fetch-err:net::ERR_FAILED`).

## 4. Local end-to-end runs

Fake portal on `127.0.0.1:8765` built like [2026-10-30.md](2026-10-30.md) section 8 (two
jobs, forms from `tests/fixtures/forms.py`, sandbox dirs with their own trackers).
Python 3.13 has no `cgi` module: parse the multipart body with
`email.parser.BytesParser(policy=email.policy.default)`. Model: default flash-lite,
`--max-actions` 12.

| Run | Result |
|---|---|
| Obscura | 12 steps, 112.6 s; both forms POSTed, server read no fields (it only parsed multipart; the body was urlencoded) and no file; both recorded `submitted_not_marked`; 23 screenshots, before and after |
| Chrome, headless | 23 steps, 128.9 s; job 101 sent with 13 fields (2 empty) and the PDF; job 202 not sent |
| Chrome, both jobs seeded in `applied.jsonl` | `already applied to http://127.0.0.1:8765/jobs/101: form actions dropped`, then the agent went back; `POSTs received: 0` |
| Same, after the `go_back` change | agent called `check_applied` on both jobs itself (`SKIP (already applied)`), the stop did not fire; `POSTs received: 0` |

Cost was not measured: the key `usage` read the same value before and after the Chrome
run and moved only minutes later, while the key is shared with other use.

**Environment trap:** `fill.py` calls `load_dotenv()` without `override`, so an
`OPENROUTER_TOKEN` exported in the shell wins over `.env`. The first Obscura run failed
every LLM call with `Error code: 401 - {'error': {'message': 'User not found.'}}`
because the shell held an old key. Runs here used `env -u OPENROUTER_TOKEN`.
